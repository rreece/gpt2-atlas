What ioi-hydra found (head level)

- The ablation: mean-ablating the name movers {9.9, 9.6, 10.0} removes 4.57 logits of direct effect.
- The result: the logit difference doesn't drop. The network repairs 103% of the damage.
- The mechanism: 10.7, the copy-suppression "brake", releases (+2.13), and backup heads in layers 10–11 step up (+2.45). 11.10 pushes back a little (−0.27).

The question in the feature basis

Does the repair rebuild the same representation, or reach the same logit difference through different features?
- Same features: the backups write the same "IO name" features the name movers would have. The repair is a restoration.
- Different features: the repair is compensation, not restoration.

Head-level accounting can't distinguish these, but SAE features can.

What I'd measure

1. IOI prompts: port the dataset generator and the mean-ablation definition from ioi-hydra into this repo, as a small python/ioi.py with attribution, rather than importing across repos.
2. Head ablation in our HF backend: a pre-hook on each layer's attention output projection that replaces the chosen heads' slices. A test against ioi-hydra's reported clean and ablated logit differences (3.38 → 3.53) guards it.
3. SAE features at the END position, clean vs. ablated, with the gate-validated SAEs at resid_pre 10 and 11 and resid_post 11.
   - How many features change, and are the ablated run's top features the clean run's?
   - Feature-level logit attribution: each feature's contribution to the logit difference, through the final LayerNorm and the IO−S unembedding direction, plus the SAE error term. Then ask whether the repair's logit difference is carried by the clean run's IO features or by new ones.
4. Bootstrap errors over prompts, as ioi-hydra used.
